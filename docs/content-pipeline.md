# 기본 어휘 콘텐츠 파이프라인 설계

> 2026-10-16 실행 방식 변경: 사용자 지시에 따라 S2 작성과 S4 검토는 API 키 없이 Codex 내부에서 원천·코드를 확인하며 수행한다. 로컬 입력·검토 명령과 작성자·검토 해시 이력을 추가했다. 아래 외부 Message Batches 설계는 선택 경로로 보존한다. 단일 의미 후보는 명시적 경고와 함께 허용하고, 철자 변형은 의미·품사에 따라 선택한다. 실제 사람의 최종 승인과 원천 대조 기록은 별도로 유지한다. 상세 결과는 [실행 안내](content-pipeline-operations.md)를 참고한다.

> 2026-10-16 학년·출시 범위 보완: 기본 목록 3,000개를 제작 대상으로 삼고, 중학 준비·중1·중2·중3·고교 연결 경로로 편성한다. 100개는 검증 표본이며 기존 300개 출시 계획은 대체한다. 공식 별표는 학년별 배정이 아니므로 [학년·레벨 점검과 구현 기준](content-grade-level-plan.md)에 따라 의미별 추천 학년·난이도·근거를 별도로 관리한다. 해당 편성 기능은 아직 미구현이다.

> 2026-10-16 PDF 활용·우선순위 조정: 사용자가 제공한 중학·고교 PDF의 단어·해설·예문·보조 자료를 먼저 정리한다. 현재 본문 2,300개와 예문 3,642쌍을 확보했다. 학년·난이도는 전수검사 중 별도로 정리한다. 원천 추출에는 학년 분류를 선행 조건으로 요구하지 않는다. [데이터 범위와 Day·Part 활용 기록](pdf-content-import.md)을 따른다.

작성일: 2026-10-16 · 상태: 파이프라인·앱 연동 구현, 실제 콘텐츠 검수·음성 제작 대기

실행 명령과 현재 구현 상태는 [실행 안내](content-pipeline-operations.md)를 참고한다. 아래에는 후속 설계도 포함되어 있으며, 사람 검수·학년 편성·출시 콘텐츠 제작이 완료됐다는 뜻은 아니다.

교육과정 기본 어휘 3,000개를 표제어로 삼아 **뜻·예문 생성 → 자동 검증 → LLM 교차 검수 → 사람 검수 → TTS 음성 → 앱 패키징**까지 반복 실행할 수 있게 만드는 파이프라인이다. 경쟁 앱 데이터는 어느 단계에서도 입력으로 쓰지 않는다([README](../README.md)의 원칙 유지).

## 0. 원칙

1. **출처를 필드 단위로 남긴다.** 모든 레코드에 표제어 출처, 생성 모델·프롬프트 버전, 검수자·검수일, 음성 엔진·음색을 기록한다.
2. **사람이 승인한 것만 배포한다.** LLM 생성과 LLM 검수는 초안과 우선순위 결정용이다. 앱에 들어가는 조건은 `human_approved` 상태다.
3. **학습 기록 ID는 바뀌지 않는다.** 콘텐츠를 다시 생성하거나 고쳐도 의미(sense) ID는 유지한다. 사용자 진행이 이 ID에 묶여 있다.
4. **재실행이 가능하다.** 단계마다 입력과 출력을 파일로 남긴다. 바뀐 항목만 다시 생성하거나 다시 합성한다(내용 해시 기준).
5. **포지셔닝을 넘지 않는다.** 기본 어휘 3,000은 "교육과정 기본기"다. 교과서 신출어와 수능 고난도 어휘는 이 목록 밖에도 많다. 그 부분은 "내 시험 범위 가져오기" 기능으로 보완하고, 3,000개만으로 내신·수능을 다 커버한다고 표시하지 않는다.
6. **공식 권장군·추천 학년·난이도를 구분한다.** `*`와 `**`를 중1·중2·중3으로 변환하지 않는다. 학년 추천은 교과서·의미별 근거를 기록하고, 난이도와 복습 경로는 별도로 둔다. 2026학년도 중3의 2015 교육과정과 2022 교육과정 자료를 섞지 않는다.

## 1. 전체 흐름

```text
[S0 표제어 확보]  교육부 고시 별책14 별표 → headwords.csv
       │
[S1 의미 설계]    표제어 → 학습할 sense 선정, sense ID 발급
       │
[S1b 학습 편성]   전수검사 중 별도 기록 → 의미별 추천 학년·난이도·복습 경로 (추가 구현)
       │
[S2 LLM 생성]     Batch API + 구조화 출력 → drafts/*.jsonl
       │
[S3 자동 검증]    스키마·예문 어휘 범위·표제어 포함·선택지 충돌 검사
       │
[S4 LLM 교차검수] 별도 프롬프트로 채점 → 플래그·심각도
       │
[S5 사람 검수]    편집자·영어교사 승인/수정/반려 → reviewed/*.jsonl
       │
[S6 TTS 음성]     승인된 텍스트만 합성 → 정규화 → ASR 역검증 → 청취 검수
       │
[S7 패키징]       단어장 구성, content 버전, 음성 팩 → assets/ + 다운로드 팩
```

## 2. 단계별 설계

### S0. 표제어 확보

- **원천:** 교육부 고시 제2022-33호 [별책 14] 영어과 교육과정의 기본 어휘 목록(약 254~290쪽, 3,000개). 고시는 저작권법 제7조의 비보호 저작물이므로 표제어 목록 자체는 자유롭게 쓸 수 있다.
- **추출:** PDF에서 텍스트를 뽑은 뒤 **두 사람이 원문과 대조**한다. 2단 편집, 하이픈, 괄호 표기 때문에 추출 오류가 나기 쉽다. 전체 개수가 원문과 맞는지 검증한다.
- **보존할 원문 표기:**
  - `*` 표시(초등 권장 800개)
  - `**` 표시(중학교·고교 공통과목 권장 1,200개). 중학교 학년별 배정 표시는 아니다.
  - 철자 변형 표기(예: `color(colour)` 형태) → `acceptedSpellings`의 근거
  - 원문 페이지 번호
- **출력:** `content/sources/curriculum_2022_basic.csv`

  | 컬럼 | 예 |
  |---|---|
  | `headword` | achieve |
  | `variants` | |
  | `elementary` | false |
  | `source_marker` | ** |
  | `source_page` | 7 (보존한 KICE PDF의 물리적 쪽수) |

- **보조 데이터(선택):** NGSL 같은 공개 빈도 목록을 학습 순서 정렬에만 내부적으로 쓴다. NGSL 1.2 본 목록의 라이선스는 아직 확인하지 못했다(관련 목록은 CC BY-SA 4.0). 사용 전에 원문 사이트에서 확인하고, 순위 값 자체는 앱에 배포하지 않는다.

### S0b. 사용자 제공 PDF의 원천 데이터 확보

`python -m tool.content.pdf_books`로 등록된 두 PDF를 추출한다. 본문 2,300개, 예문·번역 3,642쌍, 표현 300개, 관련어 153개와 어원 보조 카드 6개를 출처별로 보존한다. 원본 697쪽의 문제·정답·색인·구성도 남긴다. 이 경로는 사용자의 명시적 PDF 활용 요청에 따른 로컬 자료 정리이며, 아래 독자 생성용 프롬프트의 입력 제한과 구분한다. 세부 계약·상태는 [PDF 기록](pdf-content-import.md)에 있다.

### S1. 의미(sense) 설계 — 학습 단위 결정

현재 개발 앱은 100개 표제어의 154개 의미를 각각 학습한다. 다만 정식 승인·빌드 경로는 아직 표제어당 대표 의미 하나만 허용한다. 학년별로 필요한 다의어를 포함하려면 이 경로도 확장해야 한다.

- **제작 범위:** 대표 의미와 해당 학년에서 필요한 주요 의미·품사를 선정한다. 의미 수를 늘려 표제어 수를 부풀리지 않는다. 학년별 실제 선정은 교과서 근거와 편집 검토 후 확정한다.
- **의미 추가:** 같은 표제어 아래 새 sense를 덧붙이고, 기존 sense ID는 건드리지 않는다. 학년·난이도 조정은 ID 변경 사유가 아니다.
- **Sense ID 규칙:** `{표제어}.{품사약어}.{의미 슬러그}`. 예: `bank.n.money`, `bank.n.river`, `achieve.v.goal`.
  - 한 번 발급한 ID는 재사용·변경하지 않는다. 폐기할 때는 `deprecated_ids.json`에 후속 ID를 매핑한다.
  - 현재 MVP의 30개 ID(`achieve` 등)는 마이그레이션 표로 새 sense ID에 연결해 기존 학습 기록을 보존한다.
- **대표 의미 선정:** S2에서 LLM에게 후보 의미 2~3개와 선정 이유를 받고, 사람이 S5에서 최종 결정한다.

### S1b. 학년·레벨 편성 — 추가 구현

- 공식 원천 CSV와 별도로 `senseId`에 교육과정 버전, 최초 추천 경로, 복습 경로, 난이도, 선행 의미, 출처 근거와 검토 상태를 연결한다.
- 같은 단어의 다른 의미는 학년·난이도가 다를 수 있다. 근거가 없는 배정은 `null`과 미분류 사유로 남긴다.
- 학년별 고유 표제어 수·의미 수·신규/복습 수를 분리한다. 여러 학년에서 복습하는 의미는 같은 ID와 학습 기록을 공유한다.
- 분류 규칙, 교육과정 전환, 구현 순서와 완료 조건은 [학년·레벨 설계](content-grade-level-plan.md)를 따른다. 현재 스키마와 빌드에는 이 검사가 없다.

### S2. LLM 생성

**호출 방식**

| 항목 | 결정 |
|---|---|
| 모델 | `claude-opus-5-5`, adaptive thinking, `effort: "medium"` (파일럿에서 `high`와 비교 후 확정) |
| 실행 | Message Batches API — 비동기, 토큰 단가 50% 할인. 보통 1시간 안에 끝나고 최대 24시간. 결과는 `custom_id`(= 표제어)로 매칭 |
| 출력 형식 | 구조화 출력(`output_config.format`의 JSON Schema)으로 스키마에 맞는 JSON을 보장 |
| 프롬프트 캐싱 | 스타일 가이드와 예시(골드셋)를 담은 긴 시스템 프롬프트를 고정 접두사로 두고 `cache_control`을 건다. 요청마다 바뀌는 표제어는 맨 뒤 user 메시지에만 넣는다 |
| 요청 단위 | 표제어 1개 = 요청 1개(실패 재시도와 재생성 범위를 작게 유지) |
| 거절 대비 | `stop_reason` 확인. 교육용 어휘라 거절 가능성은 낮지만, `refusal`이나 실패 항목은 별도 목록으로 모아 재시도 |

**시스템 프롬프트 구성** (`content/prompts/generate_v1.md`, 버전 관리)

1. 대상과 목적: 한국 중·고등학생, 내신·수능 기초 어휘
2. 편집 규칙: [analysis/mvp-content-plan.json](../analysis/mvp-content-plan.json)의 `editorialRules`를 그대로 옮긴다.
   - 처음 보여 주는 뜻과 예문의 의미를 일치시킨다.
   - 다의어 뜻을 한 카드에 섞지 않는다.
   - 검증되지 않은 어원이나 억지 연상은 쓰지 않는다.
3. 문체 규칙:
   - 한국어 뜻: 사전식 짧은 형태("달성하다")
   - 설명: 해요체 한 문장, 40자 이내
   - 예문 번역: 자연스러운 해요체
4. 예문 규칙:
   - 6~14단어
   - 표제어(또는 굴절형)를 정확히 1회 포함
   - **나머지 단어는 기본 어휘 3,000(파생·굴절형 포함) 안에서만** 사용
   - 학교·일상 맥락
   - 실존 인물·브랜드·정치·폭력·연애 소재 금지
   - 유명 인용문이나 교재 문장을 재현하지 않는다.
5. 예시: 기존에 직접 쓴 30개(`assets/content/starter_vocabulary.json`)와 S5에서 승인된 골드셋을 2~4개 넣는다.
6. 독자 생성 경로에는 다른 앱·출판사 콘텐츠를 입력으로 넣지 않는다. 사용자가 명시적으로 제공·활용 요청한 PDF는 S0b의 출처 보존 경로에서 처리하며 자체 생성 문장으로 표시하지 않는다.

**출력 스키마** (`content/schema/generation.schema.json`, 요지)

```json
{
  "headword": "achieve",
  "senseCandidates": [
    {
      "pos": "v",
      "meaningKo": "달성하다",
      "meaningKoAlt": ["이루다", "성취하다"],
      "whyPrimary": "교과서·일상에서 목표 달성 의미가 압도적으로 흔함",
      "isPrimaryProposal": true,
      "explanationKo": "노력을 기울여 목표나 원하는 결과에 도달할 때 써요.",
      "collocation": "achieve a goal",
      "collocationKo": "목표를 달성하다",
      "examples": [
        {"en": "You can achieve your goal with daily practice.", "ko": "매일 연습하면 목표를 달성할 수 있어요."},
        {"en": "She achieved a high score on the test.", "ko": "그녀는 시험에서 높은 점수를 받았어요."}
      ],
      "acceptedSpellings": ["achieve"],
      "confusableHeadwords": ["receive", "believe"],
      "nearSynonymHeadwords": ["accomplish"]
    }
  ],
  "flags": []
}
```

- 예문 후보는 2개를 받고 S5에서 하나를 고른다(나머지는 추가 예문 후보로 보관).
- `confusableHeadwords`와 `nearSynonymHeadwords`는 화면에 바로 쓰기보다 **4지선다 오답 선택지에서 빼는 용도**가 먼저다(S3 참조).
- `flags`: 모델이 확신하지 못하는 부분(예: "미국·영국 의미 차이", "고시 목록 표기가 구 형태임")을 스스로 표시하게 한다.

**출력:** `content/drafts/{batch_id}.jsonl` (원본 응답, 모델·프롬프트 버전, usage 포함)

### S3. 자동 검증 (결정론적 코드)

LLM을 다시 부르지 않고 스크립트로 검사한다. 실패 항목은 수정 재요청 대상이나 사람 검수 우선순위로 보낸다.

| 검사 | 방법 | 실패 시 |
|---|---|---|
| 스키마·필수 필드 | JSON Schema 검증 | 재생성 |
| 예문에 표제어 포함 | 표제형 추출(lemmatizer)로 굴절형까지 확인 | 재생성 |
| 예문 어휘 범위 | 예문 단어를 표제형으로 바꿔 기본 어휘 3,000 + 고유 허용 목록과 대조. 범위 밖 단어가 1개를 넘으면 실패 | 재생성 또는 사람 판단 |
| 길이·문체 | 단어 수, 설명 글자 수, 해요체 어미 | 경고 |
| 중복 | 다른 표제어와 예문이 같거나 거의 같음 | 재생성 |
| **선택지 충돌** | 같은 `meaningKo`이거나 유의어 관계인 sense끼리 묶어 `distractorExclusions` 생성 | 데이터에 기록 |
| 철자 변형 | 고시 표기 변형이 `acceptedSpellings`에 있는지 확인 | 자동 보정 |
| 발음 위험 | 동형이의어 목록(`record`, `read`, `live`, `lead`, `present` 등)과 대조해 S6 청취 검수 대상으로 표시 | 플래그 |

선택지 충돌 검사가 필요한 이유: 지금 `lib/ui/study_screen.dart`의 `_choices`(319행)는 다른 단어의 뜻 중 글자가 다른 것을 아무거나 오답으로 고른다. 30개에서는 문제가 없지만 3,000개에서는 "달성하다 / 성취하다"가 함께 선택지로 나와 정답이 둘이 되는 경우가 생긴다. 오답 선택지 규칙을 다음처럼 바꿔야 한다.

- 같은 품사에서 고른다.
- `distractorExclusions`에 든 sense는 뺀다.
- 뜻의 글자 수가 비슷한 것을 고른다.

### S4. LLM 교차 검수

생성과 **다른 프롬프트**로 별도 배치를 돌려 채점한다. 사람 검수를 대신하지 않는다. 사람이 볼 순서를 정하는 용도다.

- 입력: S3를 통과한 레코드 + 채점 기준
- 채점 기준(항목별 pass/warn/fail과 한 줄 근거):
  1. 대표 의미가 학생 수준에서 가장 먼저 배울 의미인가
  2. 뜻·설명·예문의 의미가 서로 일치하는가
  3. 영어 예문이 문법적으로 자연스러운가
  4. 한국어 번역이 정확하고 자연스러운가
  5. 학생에게 부적절한 소재가 없는가
  6. 4지선다에서 정답이 하나로 정해지는가
- 출력: `content/review/llm_{batch_id}.jsonl` → 심각도 순으로 사람 검수 대기열 정렬

### S5. 사람 검수

**상태 전이**

```text
draft → auto_checked → llm_reviewed → human_approved
                                    ↘ needs_fix → (수정 또는 재생성) → auto_checked
                                    ↘ rejected (표제어 제외 또는 수동 작성)
```

- **검수자:** 영어교사나 영어 교육 편집자 1명이 1차 검수하고, 다른 1명이 표본 10%를 재검수한다. 두 사람의 판정 일치율을 기록한다.
- **도구(1차):** 스프레드시트로 내보내고 다시 가져오는 방식으로 시작한다.
  - 컬럼: 표제어, 대표 의미 선택, 예문 선택, 수정란, 판정, 메모
  - 가져올 때 S3 검증을 다시 실행해 수정 과정에서 생긴 오류를 잡는다.
  - 규모가 커지면 전용 검수 웹 화면으로 바꾼다.
- **기록:** 레코드마다 `review: {reviewer, reviewedAt, decision, editedFields[]}`
- **분량 추정:** 항목당 약 40~60초 → 3,000개 기준 약 35~50시간(1인). 1차 출시 분량부터 끊어서 진행한다(§4).
- **완료 기준:** 1차 출시 분량이 전부 `human_approved`이고, 재검수 표본에서 치명 오류(뜻 오류, 예문 의미 불일치)가 0건이어야 한다.

### S6. TTS 음성

**합성 대상** (승인된 텍스트만)

| 종류 | 언어 | 개수(1차 3,000 기준) | 용도 |
|---|---|---|---|
| 표제어 | en-US | 약 3,000 | 카드, 듣기 |
| 예문 | en-US | 약 3,000 | 카드, 듣기 |
| 한국어 뜻 | ko-KR | 약 3,000 | 듣기 모드 (선택; 없으면 기기 TTS) |

**공급자 선택**

- 후보: Google Cloud TTS, Azure, Amazon Polly 같은 상용 신경망 TTS
- 확인할 것: 생성한 음성 파일을 **앱에 넣어 배포할 수 있는지**를 해당 공급자의 서비스 약관 원문으로 확인한다. Google의 경우 "앱·미디어에 사용 가능, 경쟁 TTS 학습 금지"라는 포럼 답변만 찾았고 공식 약관 원문은 아직 보지 못했다.
- 언어별로 음색 하나를 고정하고, 엔진·음색·설정을 메타데이터에 기록한다.
- 비용: 전체가 약 25만 자 수준이라 요금표 기준 소액이다. 단가는 공급자 요금표를 따른다.

**합성 규칙**

- 표제어는 SSML로 앞뒤에 짧은 무음을 넣는다.
- 동형이의어(S3 플래그)는 품사에 맞는 발음을 SSML 발음 지정(phoneme)으로 고정한다.
- 파일 이름은 `sha1(텍스트 + 음색 + 설정)`이다. 텍스트가 바뀐 항목만 다시 합성된다.
  - 예: `audio/en/word/3f2a….m4a`

**후처리와 검증**

1. 앞뒤 무음 제거, 음량 정규화(약 -16 LUFS)
2. 인코딩: AAC(.m4a), 모노, 32~48kbps. iOS와 Android 모두에서 바로 재생된다.
3. 자동 검사:
   - 길이가 글자 수에 비해 지나치게 길거나 짧은 이상치
   - 무음 구간
   - **음성 인식으로 역검증:** 오픈소스 음성 인식 모델로 받아쓰게 해서 원문과 비교하고, 불일치하면 청취 대상에 넣는다.
4. 사람 청취: 동형이의어, 약어·숫자가 든 예문, 역검증 불일치 항목은 전수 듣는다. 나머지는 표본으로 듣는다.

**용량과 배포**

- 표제어 1초 ≈ 5KB, 예문 3초 ≈ 15KB 수준 → 영어 3,000+3,000개에 약 60MB, 한국어 뜻을 더하면 약 80MB(32kbps 기준 추정).
- 앱 번들에는 첫 단어장 분량만 넣는다. 나머지는 [analysis/apk-benchmark.json](../analysis/apk-benchmark.json)의 `audio_policy`대로 **단어장별 다운로드 팩**으로 내려받게 한다.
- 음성 파일이 없거나 받기 전이면 기기 TTS(`DeviceSpeechService`)로 대신 읽는다.

### S7. 패키징과 앱 반영

- **단어장 구성:** 단어장당 20개.
  - 목표 편성은 중학 준비·중1·중2·중3·고교 연결 경로와 의미별 난이도·선행 학습을 우선한다.
  - 공식 별표만으로 학년을 배정하지 않는다. 같은 경로 안에서 빈도와 품사 균형을 보조 기준으로 사용한다.
  - `distractorExclusions`로 묶인 의미는 같은 단어장에 몰지 않는다.
  - 현재 `make_decks()`는 초등 표시 유무로만 분리한다. 학년별 편성·다의어 정식 빌드·학년별 완성도 검사는 후속 구현이다.
- **콘텐츠 형식:** 3,000개 이상이면 JSON 하나를 통째로 읽는 방식보다 읽기 전용 `content.sqlite`가 낫다(검색, 부분 로딩). 사용자 진행 DB(`focus_voca_v1.db`)와는 계속 분리한다.
- **메타데이터:** `contentVersion`, `generatedBy`, `promptVersion`, `reviewedBy`, `ttsVoice`, `sourceList`
- **앱 쪽 변경(별도 작업):**
  1. `WordEntry` → `Headword` + `Sense` 모델. 학습 기록 키를 sense ID로 바꾸고, 기존 30개 ID를 마이그레이션한다.
  2. 오답 선택지 규칙(S3) 반영
  3. `AudioAsset` 조회: 로컬 파일 → 다운로드 팩 → 기기 TTS 순서로 대체
  4. 콘텐츠 버전이 올라갈 때 sense ID가 같으면 진행을 유지하고, 폐기된 ID는 매핑표로 이전한다.

## 6. 위험과 미결정 사항

**위험**

- **고시 목록 추출 오류:** PDF 편집 때문에 단어가 빠지거나 합쳐질 수 있다. 두 사람이 대조하는 것 외에 대안이 없다.
- **LLM 생성물의 품질 편차:** 고빈도 다의어(`get`, `take`, `run`)일수록 대표 의미 선정과 예문 품질이 흔들린다. 이런 단어는 검수자가 직접 쓰는 편이 빠를 수 있다.
- **생성 문장의 출처 문제:** 짧은 뜻풀이("달성하다")는 다른 사전과 같아도 창작성이 낮아 문제 될 가능성이 적다. 예문은 기존 출판물 문장을 재현할 가능성이 낮지만, 긴 예문은 표본을 웹에서 검색해 확인한다. 법률 자문은 아니며, 출시 전에 콘텐츠 권리 검토를 받는 것을 권장한다.

**미결정 사항 — 결정이 필요한 것**

1. 학년별 편성 범위: 3,000개 제작 원천을 중학 준비·중1·중2·중3·고교 연결로 검토하고, 교과서 근거와 의미별 편성 결과로 출시 범위를 확정한다. 기존 ‘300개 출시’와 ‘중학 핵심 800개’ 선택지는 폐기한다.
2. 검수 인력: 내부 검수인지, 영어교사 외주인지
3. TTS 공급자: 약관 원문 확인 후 확정
4. 한국어 뜻 음성: 미리 합성할지, 기기 TTS로 둘지
5. 정식 승인·빌드의 다의어 지원: 현재 단일 대표 의미 제약을 해소하고 학년별 필수 의미를 포함하는 기준 구현
